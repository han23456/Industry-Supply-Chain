## 一、企业关系网络

### 1.1 模块概述

| 项目 | 内容 |
|---|---|
| **模块名称** | 企业关系网络 |
| **路由路径** | `/enterprise/network` |
| **核心目标** | 以网络图可视化展示企业间的多维度关联关系（股权、交易、合作、供需），支持路径分析、关系强度评估、风险传导模拟，让用户看清"企业间的真实关系网" |
| **数据来源** | 工商股权数据、税务发票数据、招投标数据、供需匹配数据、企业关系表 |
| **使用角色** | 发改局、工信局、招商局、区领导 |
| **入口** | 产业链结构图谱（点击企业节点）、企业画像（查看关联关系） |

### 3.1 模块概述

| 项目 | 内容 |

| **路由路径** | `/supply-demand` |
| **核心目标** | 基于企业产品/需求目录自动匹配本地供需关系，识别供需缺口，输出撮合建议，促进产业内循环，提高本地采购率和本地销售率 |
| **数据来源** | 企业产品表、企业需求表、企业关系表、税务发票数据 |
| **使用角色** | 工信局（企业服务）、发改局（经济运行） |

### 3.2 页面布局

```

│          │                                                                  │

### 3.3 功能详解

#### 3.3.1 "谁需要我"匹配

**功能描述**：输入企业产品，自动匹配本区内需要该产品的下游企业。

**匹配度公式：**
```
matchScore = semanticSimilarity * 0.5 + categoryMatch * 0.3 + relationHistory * 0.2

- semanticSimilarity: 产品名称与需求名称的语义相似度（NLP模型，0-1）
- categoryMatch: 产品分类与需求分类是否一致（1或0）
- relationHistory: 是否已有交易历史（有=1，无=0）
```

**字段表格（匹配结果）：**

| 字段 | 类型 | 说明 | 颜色规则 |
|---|---|---|---|
| supplier_id | UUID | 供应企业ID | — |
| demander_id | UUID | 需求企业ID | — |
| match_score | Float | 匹配度 | ≥90%绿色；70-90%蓝色；<70%灰色 |
| match_reason | JSON | {semantic, category, history} | — |
| product_name | String | 供应产品 | — |
| demand_name | String | 需求产品 | — |
| status | Enum | 待撮合/已撮合/已成交 | 灰/蓝/绿 |

**业务规则：**
- 仅匹配本区企业
- 排除已建立稳定交易关系（年交易额>100万且持续2年）的企业
- 支持按匹配度、企业规模、距离排序

---

#### 3.3.2 "我需要谁"匹配

**功能描述**：输入企业需求，自动匹配本区内能提供该产品的上游供应商。

**量化规则：** 同3.3.1，方向相反

**业务规则：**
- 优先推荐有真实交易历史的企业（标注"已验证供应商"）
- 无交易历史但产品匹配的企业标注"潜在供应商"

---

#### 3.3.3 本地供需缺口识别

**功能描述**：识别本区"有需求无供应"和"有供应无需求"的环节。

**量化规则：**
```

#### 5.3.1 缺失环节识别

#### 5.3.2 补链优先级排序

**量化规则（优先级得分）：**
```
priorityScore = gapRatio * 0.3 + connectionDegree * 0.3 + revenuePotential * 0.2 + policyWeight * 0.2

- gapRatio = (benchmarkCount - actualCount) / benchmarkCount
- connectionDegree = 缺失环节连接的现有企业数 / 总企业数
- revenuePotential = 该环节行业平均营收 / 全区行业平均营收
- policyWeight = 是否为重点扶持方向（是=1，否=0.5）
```

**字段表格（补链优先级列表）：**

| 字段 | 类型 | 说明 | 排序 |
|---|---|---|---|
| priority | String | P1/P2/P3 | 按得分降序 |
| node_name | String | 环节名称 | — |

**推荐等级：**

| 总分 | 等级 | 颜色 | 操作建议 |
|---|---|---|---|

### 6.3 功能详解

#### 6.3.1 关键企业识别

**量化规则（关键指数）：**
```
keyIndex = degreeCentrality * 0.5 + betweennessCentrality * 0.5

关键企业判定：keyIndex排名Top10%
```

| 指标 | 说明 | 计算方式 |
|---|---|---|
| 度中心性 | 直接关联企业数 | degree = 交易伙伴数 + 股权关联数 + 合作伙伴数 |
| 中介中心性 | 路径中介程度 | betweenness = 经过该企业的最短路径数 / 总最短路径数 |

---

#### 6.3.2 单一依赖风险

**量化规则：**

| 风险类型 | 判定条件 | 等级 | 颜色 |
|---|---|---|---|
| 供应商依赖 | 某供应商采购额占比 > 60% | 橙色：60-80%；红色：>80% | 橙/红 |
| 客户依赖 | 某客户销售额占比 > 60% | 橙色：60-80%；红色：>80% | 橙/红 |
| 双重依赖 | 同时存在供应商依赖和客户依赖 | 自动升一级 | 红 |

---

#### 6.3.3 断链风险预警

**枚举值表格（风险类型与等级）：**
